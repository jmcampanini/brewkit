brewkit - layered Homebrew manager
==================================

brewkit manages four file types per layer:

  Brewfile.<layer>   Homebrew Bundle format: brew "name"
  Caskfile.<layer>   one cask name per line
  Headfile.<layer>   one HEAD-tracked formula per line
  Tapfile.<layer>    one tap per line: <tap> [<url>]

Several layers may be selected at once. Their entries are applied in
the layer order: the automatic "base" layer first, then the selected
layers in order, then the automatic "local" layer. An unsuffixed
Brewfile, Caskfile, Headfile, or Tapfile belongs to base, which applies
whenever one of them exists. The *file.local files belong to local,
which applies whenever one of them exists; it is meant for
machine-specific overrides and is gitignored by convention. Neither
automatic layer can be selected by name.


Configuration
-------------

A brewkit.toml in the current working directory is loaded by default;
pass --config <path> to use a different file. An implicit missing file
is allowed; an explicit missing or empty path is an error. Running with
no config falls back to defaults:

  dir        = "."
  layers     = []
  env_layers = []
  fail_fast  = true

Keys:
  dir         Directory holding the layer files. Relative paths are
              resolved by the process current working directory, not
              by the config file's directory.
  layers      Raw layer list.
  env_layers  Names of environment variables whose comma-separated
              values append layers to `layers`, read in list order.
              A blank or whitespace-padded name is an error.
  fail_fast   Stop on first error (true) or report at end (false).

BREWKIT_LAYERS replaces the raw `layers` value:

  BREWKIT_LAYERS=work,personal brewkit brew

Layer flags replace file/env raw layers. Use --layers for a
comma-separated list, or repeat --layer to add one layer per flag:

  brewkit --layers work,personal brew
  brewkit --layer work --layer personal brew

An explicitly empty list such as --layers "" or BREWKIT_LAYERS= clears
the raw layers. Flag and environment items are trimmed; a TOML item is
used exactly as written. Any other blank item is an error.

The effective layers are derived once: the raw `layers`, then the
values of the variables named by `env_layers` appended in order, then
de-duplication keeping the last occurrence of each name, then
validation. A layer name is 1 to 64 characters of lowercase letters and
digits in groups separated by single hyphens (work, work-laptop, 2026).
The names "base" and "local" cannot be selected. The apply commands
walk the layer order: base when an unsuffixed file exists, the
effective layers, then local when a *file.local exists. An empty
selection is fine; base and local still apply when available, and a
layer with no file of a kind is skipped.

Print the loaded config and the effective values any time with:

  brewkit config

Add --provenance to append the source of every field.


Commands
--------

  brewkit tap  [TAP]      Register and trust listed taps.
  brewkit brew [FORMULA]  Apply Brewfile entries.
  brewkit head [FORMULA]  Apply Headfile entries (SHA-idempotent).
  brewkit cask [CASK]     Apply Caskfile entries (greedy upgrades).
  brewkit lint            Validate layer files.
  brewkit config          Print loaded config and effective values.
  brewkit docs            Print this manual.

Each apply command accepts an optional positional arg to scope the
operation to a single item, looked up by name (full or short, after
the last `/`) across the layers. `brewkit lint`,
`brewkit config`, and `brewkit docs` take no positional arg. An
unexpected arg, or a second arg on an apply command, is a usage error:
brewkit exits 1 before reading any file or running any program.

Apply-command flags:
  --hide-unchanged  suppress per-item lines for already satisfied
                    entries; summaries still count them

Global flags:
  --config PATH          explicit path to brewkit.toml
  --layers LIST          comma-separated layers; replaces file/env raw layers
  --layer NAME           add one layer; may be repeated; replaces file/env raw layers
  --dry-run              compute changes without applying
  --output-prefix TEXT   prefix brewkit command output lines
                         (excludes help/version)
  -v, --verbose          stream raw brew output for every operation
                         (cannot be used with --quiet)
  -q, --quiet            errors-only output for operational commands
                         (cannot be used with --verbose)


Output
------

Default output streams per-item changes immediately followed by a
one-line summary. Symbols:

  +  added (newly installed) or trusted (existing tap newly trusted)
  ↑  upgraded (with old → new where available)
  ✓  already up to date
  ⊘  skipped notice (e.g. missing layer file)
  ✗  error

Interactive color output automatically selects Catppuccin Latte for a
light terminal background and Catppuccin Frappe for a dark background.
brewkit checks the COLORFGBG hint first. For non-quiet output without
a hint, it queries when standard input and the selected output are
terminals; otherwise it falls back to Frappe. Upgrade arrows use the
palette's mauve accent; spinner glyphs use its teal accent; details,
notices, and progress messages use its secondary text.
Colors are downsampled for 16-color and 256-color terminals. Set any
nonempty NO_COLOR value to disable color without disabling progress.
Transient progress messages and truncation tails use three ASCII
periods (...), not a single ellipsis character.

On any non-zero brew exit the captured stdout/stderr is printed in
full regardless of verbosity.

Use --output-prefix TEXT to prefix output emitted by brewkit commands,
including durable command output, errors, and transient progress frames.
Help and version output are intentionally not prefixed.

With -q/--quiet, operational commands (tap, brew, head, cask, lint)
emit only errors. Successful quiet operational runs print nothing: no
per-item success lines, skipped-file notices, restart notices, or final
summary. Lint violations are actionable errors, so `brewkit -q lint`
still prints individual violations and exits non-zero; clean quiet lint
prints nothing. `brewkit -q config` and `brewkit -q docs` still print
their requested payloads. --quiet and --verbose cannot be used
together.


File formats
------------

Every file supports `# comment` lines, blank lines, and inline
trailing `# description` comments. Files are read regardless of
sort order; alphabetical sorting is enforced by `brewkit lint`.

Brewfile.<layer> - Homebrew Bundle subset.
  brew "name"
  brew "name"            # description
  brew "user/tap/name"   # description for fully qualified entries

  Only `brew "..."` and `brew "..." # description` are recognized.
  Other Bundle directives (tap, cask, mas, vscode) are reported as
  unknown shape by `brewkit lint`. Use Tapfile/Caskfile instead.

Caskfile.<layer>, Headfile.<layer>
  name
  name                       # description

  One token per line. Headfile may use fully qualified
  `user/tap/formula` names.

Tapfile.<layer>
  tap-name
  tap-name <url>
  tap-name <url>             # description

  The URL is optional; supply it for taps Homebrew cannot locate
  via its default index.

  Listing a tap authorizes trust for the whole tap, including its
  formulae, casks, and commands. brewkit tap reads installed taps and
  effective trust once with `brew tap-info --installed --json=v1`.
  It does not query package inventory or available upgrades. The query
  sets HOMEBREW_NO_GITHUB_API=1 to skip GitHub metadata requests;
  Homebrew may still need its formula-index cache. Homebrew must support
  `brew trust --tap` and report trust in tap-info JSON;
  missing or invalid trust data fails. Run `brew update` to update it.

  A missing tap is trusted first with `brew trust --tap <url>` when a URL
  is supplied, or `brew trust --tap <tap>` otherwise. It is then registered
  with `brew tap <tap> [<url>]`. Homebrew requires trust before verifying
  formulas and casks during registration. An installed but untrusted tap
  needs only `brew trust --tap <tap>`; Homebrew resolves its existing
  remote and persists trust. Official taps are already trusted.

  New registrations print '+ name registered and trusted' and count as
  added. Trust-only changes print '+ name trusted' and count as trusted.
  Only registered, trusted taps count as up-to-date. --hide-unchanged
  hides those lines while keeping their summary count. If trust fails,
  registration is not attempted. If trust succeeds but registration fails,
  trust is retained and the entry fails. A later run can retry registration.
  fail_fast applies to both operations.

  --dry-run previews registration and trust without changing either.
  Later duplicate entries see projected successful changes, as in a
  real run. Removing an entry never untaps it or revokes trust.

  Trust brewkit's own tap before installing or upgrading brewkit:
    brew trust --tap https://github.com/jmcampanini/brewkit
    brew tap jmcampanini/brewkit https://github.com/jmcampanini/brewkit
    brew install --HEAD jmcampanini/brewkit/brewkit

  For an existing installation, after trusting its tap:
    brew upgrade --fetch-HEAD brewkit


Editing layer files
-------------------

Layer files are designed to be edited by humans AND by LLMs.
Conventions enforced by `brewkit lint`:

  1. Each entry on its own line, alphabetically sorted within its
     section. Sections are delimited by blank lines; comment-only
     lines (including HACK headers) are part of the surrounding
     section, not delimiters.
  2. Trailing description comments use the format `name  # text`
     with at least two spaces before the `#`.
  3. Every `#` comment marker is followed by exactly one space:
     `# text`, not `#text` or `#  text`.
  4. Brewfile/Caskfile/Headfile entries should carry a trailing
     description. Tapfile entries are exempt.
  5. No trailing whitespace and no consecutive blank lines.


brewkit lint rules
------------------

Each rule has a stable ID for reference in error messages.

  sort-order              Entries within a section are alphabetically
                          sorted by name.
  trailing-description    Each entry should have a trailing
                          # description (skipped for Tapfile).
  comment-space           # markers must be followed by exactly one
                          space.
  inline-comment-gap      Trailing inline comments must be preceded
                          by at least two spaces.
  no-consecutive-blanks   At most one blank line in a row.
  no-trailing-whitespace  No trailing spaces or tabs on any line.
  known-entry-shape       Each non-blank, non-comment line parses
                          as a valid entry for its file type.

`brewkit lint` exits non-zero when any violations are found.
`-v` includes the offending line content. `-q` prints individual
violations only, and prints nothing when there are no violations.


HEAD formula handling
---------------------

`brewkit head` uses a SHA-idempotency strategy for valid HEAD
entries:

  1. If the formula is installed but not as HEAD (the linked keg
     version is not `HEAD-...`), report an error and do not
     auto-convert it.
  2. If the formula has no HEAD source, report an error and do not
     install or reinstall it.
  3. If the formula is not installed and has a HEAD source, install
     with `brew install --head --formula <name>`
     (HOMEBREW_NO_GITHUB_API=1).
  4. If installed as HEAD, fetch the latest available HEAD short
     SHA from the formula's HEAD source repository and compare
     against the installed SHA. Reinstall only when they differ.

This avoids slow rebuilds when the upstream repo has not moved and
keeps invalid Headfile entries actionable.


Cask handling
-------------

`brewkit cask` upgrades casks with `--greedy`, matching the
existing dotfiles convention. Upgraded casks are listed in a
"Restart these apps to apply upgrades" notice at the end of
the run.
